## 1. Общая информация о задании

Задание 26 проверяет умение обрабатывать целочисленную информацию с использованием сортировки (так сказано в спецификации). К заданию приложен текстовый файл. В нем тысячи строк (в демоверсии 2027 это одна служебная строка и 15 001 строка журнала), руками его не разобрать, поэтому нужна программа на Python.

Что важно знать с самого начала.

- В ответе всегда два числа. Первое обычно проще (количество или номер), второе требует доработать решение.
- Сюжет каждый год новый или слегка измененный. Готового шаблона на все случаи нет, зато приемы повторяются (чтение файла, сортировка, один проход по данным, словарь).
- Это одно из двух заданий экзамена, за которые дают 2 балла (второе это №27).

## 3. Как читать файл

В начале файла стоит шапка, то есть одна или две служебные строки с числами (количество строк, вместимость, число ячеек). Состав шапки меняется от задачи к задаче, поэтому каждый раз сверяй ее с условием. Дальше идут строки с данными.

Шапка из одного числа, в каждой строке одно число.

```python
f = open('26.txt')
n = int(f.readline())
a = [int(s) for s in f]
```

Шапка из двух чисел, в каждой строке два числа.

```python
f = open('26.txt')
n, k = map(int, f.readline().split())
a = []
for s in f:
    x, y = map(int, s.split())
    a.append((x, y))
```

Шапка из двух строк (в первой число ячеек, во второй число заявок), в каждой строке данных два числа.

```python
f = open('26.txt')
k = int(f.readline())
n = int(f.readline())
a = []
for s in f:
    x, y = map(int, s.split())
    a.append((x, y))
```

В строке не только числа (время, номер клиента и объем, как в демоверсии 2027).

```python
f = open('26.txt')
n, k = map(int, f.readline().split())
a = []
for s in f:
    t, c, v = s.split()
    a.append((t, int(c), int(v)))
```

Строки удобно хранить кортежами. Кортеж это несколько значений в круглых скобках, например `(5, 7)`. Значения внутри кортежа дальше называются полями. Кортежи сравниваются сначала по первому полю, при равенстве по второму, и это пригодится при сортировке.

---

## 4. Сортировка в Python

| Что нужно | Код |
|---|---|
| по возрастанию | `a.sort()` |
| по убыванию | `a.sort(reverse=True)` |
| по второму полю кортежа | `a.sort(key=lambda x: x[1])` |
| по первому полю по убыванию, при равенстве по второму по возрастанию | `a.sort(key=lambda x: (-x[0], x[1]))` |
| новый список, старый не меняется | `b = sorted(a)` |
| два самых больших числа после `a.sort()` | `a[-1]` и `a[-2]` |
| ключ словаря с наибольшим значением | `max(d, key=d.get)` |

То, по чему сравнивают элементы списка при сортировке, называют ключом сортировки (в коде он записан после `key=`). Сортировку сразу по нескольким полям (четвертая строка таблицы) называют сортировкой по составному ключу.

Время в формате `ЧЧ:ММ:СС` с ведущими нулями можно сравнивать как строки. Например, `'09:05:00' < '11:59:59'` дает `True`.

Подробнее про списки, словари и `lambda` написано в файле [Python для ЕГЭ](https://github.com/scharfff/spbpu-inf-course/blob/2027/Python_для_ЕГЭ.md).

## 5. Общий план решения

1. Прочитать шапку и строки файла. Обычно строки складывают в список кортежей. Если их достаточно обработать по одной в порядке файла, список не нужен.
2. Отсортировать список по нужному ключу. Сортировка не нужна, если строки уже идут в нужном порядке (журнал по времени). Если в условии важен исходный порядок строк, сортируют копию списка.
3. Сделать один проход по данным и на каждом шаге обновлять нужные переменные (счетчик, сумму, последний взятый элемент, словарь).
4. Отдельно подумать про второе число ответа. Часто его нельзя получить тем же действием, что и первое, и нужен дополнительный шаг (отсортировать результаты, выбрать из оставшихся элементов, учесть ограничение из условия).
5. Проверить программу на примере из условия и только потом запускать на файле.

Как проверить программу на примере. Сохрани пример из условия вместе с шапкой в отдельный файл (например, `test.txt`) без пустых строк в конце, запусти программу на нем и сверь ответ. После проверки верни в программе имя файла `26.txt`.

## 7. Разбор. Демоверсия 2027

Сервер принимает запросы. Данные каждого запроса он кладет в раздел памяти вместимостью `K` Кбайт. Если очередной запрос в раздел не помещается, сервер сначала делает резервную копию всего накопленного, очищает раздел и только потом кладет туда этот запрос.

В первой строке файла записаны `N` (число строк журнала) и `K`. В каждой следующей строке записаны время запроса в формате `ЧЧ:ММ:СС`, номер клиента и объем данных в Кбайт. Объем одного запроса всегда меньше `K`.

Нужно найти два числа. Первое это номер клиента, который передал больше всего данных за весь журнал. Второе это сумма объемов двух самых больших резервных копий, сделанных не позднее `11:59:59`.

### Пример из условия

В примере `K` равно 140 000.

| Время | Клиент | Объем | В разделе до запроса | Помещается | Копия | В разделе после |
|:-:|:-:|:-:|:-:|:-:|:-:|:-:|
| `01:01:01` | 101 | 20 000 | 0 | да |  | 20 000 |
| `03:03:03` | 202 | 110 000 | 20 000 | да |  | 130 000 |
| `05:05:05` | 101 | 90 000 | 130 000 | нет | 130 000 | 90 000 |
| `07:07:07` | 303 | 62 000 | 90 000 | нет | 90 000 | 62 000 |
| `10:10:10` | 101 | 48 000 | 62 000 | да |  | 110 000 |
| `15:15:15` | 202 | 12 000 | 110 000 | да |  | 122 000 |
| `21:21:21` | 303 | 120 000 | 122 000 | нет | 122 000 | 120 000 |
| `23:23:23` | 404 | 134 000 | 120 000 | нет | 120 000 | 134 000 |

Клиенты передали 158 000 (номер 101), 122 000 (номер 202), 182 000 (номер 303) и 134 000 (номер 404). Больше всех передал клиент 303. Не позднее `11:59:59` сделаны две копии, 130 000 и 90 000, их сумма 220 000. Ответ для примера `303 220000`.

Из таблицы видны три правила, на которых чаще всего ошибаются.

- Время копии это время запроса, который не поместился.
- В копию уходит то, что накопилось до этого запроса. Сам запрос попадает уже в следующую копию.
- То, что осталось в разделе в конце журнала, копией не считается.

### Программа

```python
f = open('26.txt')
n, k = map(int, f.readline().split())

total = {}        # клиент и сколько он передал за весь журнал
used = 0          # сколько сейчас занято в разделе
copies = []       # объемы копий, сделанных не позднее 11:59:59

for s in f:
    t, c, v = s.split()
    c, v = int(c), int(v)
    total[c] = total.get(c, 0) + v
    if used + v > k:              # запрос не помещается
        if t <= '11:59:59':
            copies.append(used)   # в копию уходит накопленное
        used = 0
    used += v

best = max(total, key=total.get)
copies.sort()
print(best, copies[-1] + copies[-2])
```

На примере из условия программа печатает `303 220000`, на файле демоверсии `7040 52204`. Это совпадает с официальным ответом ФИПИ.

Программа и файл демоверсии лежат в папке `Решение` (файлы `2601.py` и `2601.txt`). Там программа открывает файл под именем `2601.txt`.

Сортировка в этой программе нужна в одном месте, она упорядочивает список объемов копий, чтобы взять два самых больших. Строки журнала программа читает подряд и не переставляет, потому что в файле демоверсии они уже идут по возрастанию времени. В условии такой порядок прямо не обещан. Если в другом файле строки окажутся не по времени, журнал сначала нужно прочитать в список и отсортировать по времени.

## 8. Типичные ошибки

| Ошибка | Как избежать |
|---|---|
| Шапка прочитана не так (перепутаны числа, пропущена вторая служебная строка) | Сверить первые строки файла с условием |
| Числа ответа записаны в другом порядке | Перечитать в условии фразу про ответ (блок «Выходные данные» или слова «запишите в ответе»), порядок чисел указан там. Если такой фразы нет, порядок задает сам вопрос задачи. За перепутанные числа ставят 1 балл вместо 2 |
| Перепутаны строгое и нестрогое сравнение, то есть `<` и `<=` («не позднее», «не менее чем на», «со следующей минуты») | Выписать граничный случай, то есть значение ровно на границе (например, запрос ровно в `11:59:59`), и по тексту условия решить, подходит ли он. Если такой случай есть в примере из условия, проверить на нем программу |
| Решение взято по памяти от похожей задачи | Сюжет повторяется, вопрос часто меняется. Читать, что именно спрашивают |
| Список отсортирован, хотя в условии важен исходный порядок строк | Исходный список не менять, сортировать его копию (`b = sorted(a)`) |
| Программа не проверена на примере из условия | Сначала получить ответ примера, потом запускать на файле |
| Найдено только одно число, и ответ не записан | Одно верное число на своем месте дает 1 балл |

В некоторых задачах пример из условия посчитан для одного значения параметра, а сама задача задана для другого (в задачах про коробки и коржи пример посчитан для разницы 3, а задача для разницы 8 или 9). Такое число записано в тексте условия, а не в шапке файла, поэтому его удобно держать в переменной. На время проверки в нее ставят значение из примера, а перед запуском на файле возвращают значение из задачи.
